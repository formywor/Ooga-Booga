# Property security update — detection, buffered recording, audio and reconnect

Replace the files in the update ZIP in the matching API and website GitHub repositories. Deploy the API first, then the website. If you use the included Cloudflare security-header Worker, publish its updated file too; phone microphone permission now needs its page-specific exception.

Put your MP3 here: `outputs/main-website/alarm.mp3`, beside `property-security.html`. Upload it to the website repository root so it serves at `https://scriptnovaa.com/alarm.mp3`. Do not put it in the API. The system uses this file after the countdown. No alarm file is bundled in this update.

On the PC, reload the dashboard, connect and click Enable PC audio / test speaker. The control key remains in this tab's session storage for refreshes. Camera configuration, voice preferences and armed state remain in local storage. Refresh/reconnect does not disarm. Closing the browser still stops monitoring, and audio autoplay rules can require pressing Enable PC audio after refresh. Background tabs may throttle detection/buffering; keep the dashboard visible and the PC awake. No claim of continuous monitoring while the browser is closed.

On the phone, reload/open the pairing link and allow microphone permission when requested. Include microphone audio can be switched off. Pairing, microphone selection and capture-running preferences are saved locally; the phone retries capture when Safari is visible. Browser permissions can still require tapping Start camera. Automatic dashboard reconnection retries with backoff; keep one dashboard per camera slot. This does not remove the TURN requirement for difficult cellular networks.

Detection uses the more accurate MobileNet V2 COCO-SSD model, starts at 45% confidence, and retains an active track at 35%. A 3-second detection gap no longer means immediate departure. Once a person enters the zone, tracking follows the nearest visible person throughout the frame until no person is seen for 3 seconds. This is software bounding-box tracking, not a motorized camera pan or personal identity recognition. The warning says they are being recorded and an alarm will follow. The warning is allowed to finish before countdown. Detection failures remain possible; test your actual scene.

Recording uses a bounded 10-second JPEG/PCM ring (5 video frames per second, 480×270) while the camera is connected and PC audio is enabled. On detection while armed it preserves available prior footage, continues through the event, and ends 5 seconds after the last raw person detection. Events longer than 25 seconds are split into numbered, standalone playable parts so each stays near the existing 1 MB API cap. The first event after startup has only as much prebuffer as exists. Encoding is performed on the PC after each part closes and takes approximately the part's duration; upload is not instant. Audio is included when the phone sends it. When the camera disconnects, a five-second tail shows the last received image with an offline label and silence where no audio was received. It cannot capture new footage after a disconnect. Clips above the API cap or failed uploads appear with a local download link. Browser shutdown can interrupt queued saves; wait for the saved confirmation before closing.

The API retains the latest 20 **parts**, not 20 complete long events, for seven-day access retention. Listing/uploading performs expiry cleanup; no scheduler is added. Realtime Database is used, not Firebase Storage. Extended events can consume the 20-part quota quickly. No phone notifications are added.

For spoken cancellation, choose a Voice camera and enable voice cancellation on the PC. Use supported current desktop Chrome or Edge. Say “cancel”, wait for the prompt to finish, then say “two two four four” (2244). The code is verified by the API; cancel alone does not disarm. Five attempts per minute are allowed. The default is 2244 as requested; optional Vercel `PROPERTY_VOICE_ADMIN_CODE` overrides it with another four-digit value. The code is not a voice identity check; anyone who knows it can speak it. Recognition can use the browser's online speech service. It requires microphone audio from the selected phone. Other browsers may not support recognition from remote audio tracks; the dashboard displays failures instead of falling back silently to the PC microphone. Only one selected camera supplies voice commands at a time. Loud speakers, sirens, accents and network failures may interfere; Silence & disarm always remains available.

Verify after deployment: walk/move through the scene; briefly occlude a person; leave the frame; test audio MP3 after 3-2-1; check clips include prior footage and tail; disconnect and reconnect Wi-Fi; refresh while armed; test cancel with wrong and correct codes. These device-level checks are not replaced by automated tests.

Audio arrangement: warnings, countdown, code prompts and alarm.mp3 play from the PC speaker. Microphone input comes from the selected phone through WebRTC. The PC microphone is not used automatically. Enable microphone capture on the phone and choose that camera under Voice camera on the dashboard.
