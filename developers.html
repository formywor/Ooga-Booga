Developer API · Free early access

Build something with Nebula.

One key, standard HTTPS, and room for your own tools.

Open Nebula → Features → Developer API. Sign in with a verified email, create a key, and copy it once. Keep the key in your server environment as NEBULA_API_KEY. Revoke unused keys from the same panel.

Base URL: https://api.scriptnovaa.com/v1

Free access, clear limits

All models offered by this API are free. Nebula Spark is excluded. Availability is shown by GET /v1/models; a disconnected research model is not automatically served by a different model. D2 Preview is separate from the research checkpoint being trained.

Make your first request

Any language with an HTTPS client works: Python, JavaScript, TypeScript, Java, C#, Go, Rust, PHP, Ruby, Swift, Kotlin and more. The chat response and function-call shapes are OpenAI compatible. This initial release supports text and non-streaming chat completions.

cURL
curl https://api.scriptnovaa.com/v1/chat/completions \
  -H "Authorization: Bearer $NEBULA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"nebula-ultra","messages":[{"role":"user","content":"Explain this idea simply."}]}'
Python
import os, requests
response = requests.post(
    "https://api.scriptnovaa.com/v1/chat/completions",
    headers={"Authorization": "Bearer " + os.environ["NEBULA_API_KEY"]},
    json={"model": "nebula-ultra", "messages": [{"role": "user", "content": "Hello!"}]},
    timeout=90,
)
response.raise_for_status()
print(response.json()["choices"][0]["message"]["content"])
JavaScript / TypeScript (server)
const response = await fetch("https://api.scriptnovaa.com/v1/chat/completions", {
  method: "POST",
  headers: {
    "Authorization": `Bearer ${process.env.NEBULA_API_KEY}`,
    "Content-Type": "application/json"
  },
  body: JSON.stringify({model: "nebula-ultra", messages: [{role: "user", content: "Hello!"}]})
});
if (!response.ok) throw new Error(`Nebula returned ${response.status}`);
console.log((await response.json()).choices[0].message.content);
OpenAI-compatible SDK (Python)
from openai import OpenAI
import os
client = OpenAI(api_key=os.environ["NEBULA_API_KEY"], base_url="https://api.scriptnovaa.com/v1")
reply = client.chat.completions.create(model="nebula-ultra", messages=[{"role":"user","content":"Hello!"}])
print(reply.choices[0].message.content)
C#
using System.Net.Http.Headers;
using System.Net.Http.Json;
var client = new HttpClient();
client.DefaultRequestHeaders.Authorization = new AuthenticationHeaderValue("Bearer", Environment.GetEnvironmentVariable("NEBULA_API_KEY"));
var response = await client.PostAsJsonAsync("https://api.scriptnovaa.com/v1/chat/completions", new {
  model = "nebula-ultra", messages = new[] { new { role = "user", content = "Hello!" } }
});
response.EnsureSuccessStatusCode();
Console.WriteLine(await response.Content.ReadAsStringAsync());

Endpoints

GET /v1/models lists model IDs and availability. POST /v1/chat/completions generates an answer. GET /v1/usage shows your API usage and limits. Every endpoint requires Authorization: Bearer YOUR_NEBULA_KEY.

Chat parameters: model, messages, optional max_completion_tokens (or max_tokens), temperature, tools, and tool_choice (auto, none or required). Set stream to false or omit it. Images, audio, hosted web tools and streaming are not supported by this endpoint.

Your own tools and Cloud

Developer keys cannot open Nebula Cloud, use its browser, run hosted code, read account memories or access saved chats. Ultra and D2 can return calls to functions declared by your application. Your server validates and runs those functions in your own environment, then submits the results.

{"model":"nebula-d2","messages":[{"role":"user","content":"What is 7 times 8?"}],"tools":[{"type":"function","function":{"name":"multiply","description":"Multiply two numbers in my own app","parameters":{"type":"object","properties":{"a":{"type":"number"},"b":{"type":"number"}},"required":["a","b"],"additionalProperties":false}}}]}

If the response contains message.tool_calls, append that assistant message unchanged to your history. Run each permitted function yourself, then append a message such as {"role":"tool","tool_call_id":"THE_RETURNED_ID","content":"56"} and make another completion request. Check the requested function and arguments against your own permissions before execution. Tool results are data, not authority to perform more actions.

Handle errors

413 means the request or reserved token budget is too large; shorten the history or reduce the output limit. 401 means the key is invalid or revoked. 400 means the payload or feature is unsupported. 429 means an account or service limit was reached; 503 means a model is busy or not connected. Honor Retry-After, use bounded backoff, and avoid parallel retry loops. Never place your Nebula key in public client code.

Privacy and control

Developer requests do not become chats, saved memories or training samples. Usage counters, key names and timestamps are stored for account control and limits. Keys are shown once; only a hash is retained. Your request is processed by the services needed to generate the response under their applicable retention policies.
