From your first request to a real device.

The API works from any language or hardware capable of HTTPS and JSON. The model runs remotely, so your Raspberry Pi, computer or embedded device sends the request and receives the answer. No local AI model installation is needed.
Three setup steps
  1. Sign in with a verified email and create a named API key.
  2. Save it as NEBULA_API_KEY on your server or in protected device configuration.
  3. Call https://api.scriptnovaa.com/v1/chat/completions using nebula-ultra.
For phones, browsers or devices that other people can inspect, use your own small server as a relay. Hardware must verify HTTPS certificates; never disable certificate verification to make a connection work. Keep API keys out of public firmware and repositories.
Make your first request
Any language with an HTTPS client works: Python, JavaScript, TypeScript, Java, C#, Go, Rust, PHP, Ruby, Swift, Kotlin and more. The chat response and function-call shapes are OpenAI compatible. This initial release supports text and non-streaming chat completions.
cURL
curl https://api.scriptnovaa.com/v1/chat/completions \
  -H "Authorization: Bearer $NEBULA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"nebula-ultra","messages":[{"role":"user","content":"Explain this idea simply."}]}' 
Python
import os, requests
response = requests.post(
    "https://api.scriptnovaa.com/v1/chat/completions",
    headers={"Authorization": "Bearer " + os.environ["NEBULA_API_KEY"]},
    json={"model": "nebula-ultra", "messages": [{"role": "user", "content": "Hello!"}]},
    timeout=90,
)
response.raise_for_status()
print(response.json()["choices"][0]["message"]["content"])

Endpoints
GET /v1/models lists model IDs and availability. POST /v1/chat/completions generates an answer. GET /v1/usage shows your API usage and limits. Every endpoint requires Authorization: Bearer YOUR_NEBULA_KEY.
Chat parameters: model, messages, optional max_completion_tokens (or max_tokens), temperature, tools, and tool_choice (auto, none or required). Set stream to false or omit it. Images, audio, hosted web tools and streaming are not supported by this endpoint.
Your own tools and Cloud
Developer keys cannot open Nebula Cloud, use its browser, run hosted code, read account memories or access saved chats. Ultra and D2 can return calls to functions declared by your application. Your server validates and runs those functions in your own environment, then submits the results.
{"model":"nebula-ultra","messages":[{"role":"user","content":"What is 7 times 8?"}],"tools":[{"type":"function","function":{"name":"multiply","description":"Multiply two numbers in my own app","parameters":{"type":"object","properties":{"a":{"type":"number"},"b":{"type":"number"}},"required":["a","b"],"additionalProperties":false}}}]}
If the response contains message.tool_calls, append that assistant message unchanged to your history. Run each permitted function yourself, then append a message such as {"role":"tool","tool_call_id":"THE_RETURNED_ID","content":"56"} and make another completion request. Check the requested function and arguments against your own permissions before execution. Tool results are data, not authority to perform more actions.
Handle errors
413 means the request or reserved token budget is too large; shorten the history or reduce the output limit. 401 means the key is invalid or revoked. 400 means the payload or feature is unsupported. 429 means an account or service limit was reached; 503 means a model is busy or not connected. Honor Retry-After, use bounded backoff, and avoid parallel retry loops. Never place your Nebula key in public client code.
Privacy & control
Developer requests are not saved as Nebula chats, memories or training samples. The platform stores bounded request metadata for metrics and troubleshooting. Full API keys are shown once and stored as hashes. Sign in with a verified email to manage keys and codes. Public documentation remains available to everyone.
